# Αντίγραφα ασφαλείας της βάσης — αναλυτικός οδηγός

Γραμμένο για να το ακολουθήσεις χωρίς να ξέρεις PostgreSQL ή PowerShell.

---

## 1. Τι κάνουμε εδώ και γιατί

Τα δεδομένα της εφαρμογής ζουν σε μια βάση PostgreSQL στη **Neon**. Στο δωρεάν
πακέτο της, η Neon κρατά ιστορικό **μόνο 6 ωρών**:

| | Δωρεάν πακέτο Neon |
|---|---|
| Επαναφορά σε προηγούμενη στιγμή | 6 ώρες πίσω |
| Χειροκίνητα snapshots | 1 |
| Προγραμματισμένα αντίγραφα | δεν υπάρχουν |

Αυτό σημαίνει τρία πράγματα:

1. Λάθος που θα το καταλάβεις **αύριο**, δεν διορθώνεται από τη Neon.
2. Αν χαθεί ο λογαριασμός σου στη Neon, χάνονται **και τα δεδομένα και το ιστορικό**.
3. Χρειάζεσαι δικά σου αντίγραφα, εκτός Neon.

Αυτό κάνουν τα scripts αυτού του φακέλου: κάθε βράδυ κατεβάζουν **ολόκληρη τη
βάση** σε ένα αρχείο, το κλειδώνουν με κωδικό, το βάζουν σε δύο μέρη και κρατούν
ιστορικό μηνών. Και όταν χρειαστεί, το γυρίζουν πίσω.

> **Προσοχή στη διαφορά:** το κουμπί «Λήψη Πλήρους Backup» μέσα στην εφαρμογή
> **δεν είναι αντίγραφο ασφαλείας**. Είναι εξαγωγή των δεδομένων ενός πελάτη σε
> Excel, για να τα δει άνθρωπος. Δεν περιέχει το σχήμα της βάσης και δεν
> επαναφέρεται πουθενά. Είναι σαν φωτογραφία του αυτοκινήτου: χρήσιμη, αλλά δεν
> οδηγείται.

## 3. Τα αρχεία του φακέλου — τι είναι το καθένα

| Αρχείο | Τι κάνει | Πόσο συχνά το τρέχεις |
|---|---|---|
| `init-secrets.ps1` | Αποθηκεύει το connection string και τον κωδικό κρυπτογράφησης | Μία φορά |
| `install-task.ps1` | Λέει στα Windows να τρέχουν το αντίγραφο κάθε μέρα στις 03:00 | Μία φορά |
| `backup-db.ps1` | **Παίρνει το αντίγραφο.** Τρέχει μόνο του κάθε βράδυ | Αυτόματα |
| `verify-backup.ps1` | Δοκιμάζει ότι το αντίγραφο όντως επαναφέρεται | Μία φορά τον μήνα |
| `restore-db.ps1` | Επαναφέρει **ολόκληρη** τη βάση | Σε έκτακτη ανάγκη |
| `restore-tenant.ps1` | Επαναφέρει **μία εταιρεία**, αφήνοντας τις άλλες ανέπαφες | Σε έκτακτη ανάγκη |
| `settings.ps1` | Ρυθμίσεις: διαδρομές, πόσα αντίγραφα κρατάμε | Μόνο αν αλλάξεις κάτι |
| `settings.local.ps1` | Δικές σου αλλαγές στις ρυθμίσεις (δεν μπαίνει στο git) | Προαιρετικό |
| `lib\common.ps1` | Ο κοινός κώδικας. **Μην το τρέχεις μόνο του** | Ποτέ |

## 4. Η πρώτη φορά — τρία βήματα

Άνοιξε PowerShell και πήγαινε στον φάκελο:

```bash
cd C:\Users\patsg\source\repos\RentApp\tools\backup
```

**Βήμα 1 — πες του πού είναι η βάση και με τι κωδικό κλειδώνουμε:**

```bash
.\init-secrets.ps1
```

Θα σου ζητήσει δύο πράγματα:

- **Connection string**: αντίγραψέ το από τη Neon (Dashboard → το project → *Connect*).
  Μοιάζει με `postgresql://neondb_owner:κωδικός@ep-xxx.eu-central-1.aws.neon.tech/neondb?sslmode=require`.
- **Κωδικό κρυπτογράφησης**: τον επιλέγεις εσύ, τουλάχιστον 12 χαρακτήρες.

Καθώς πληκτρολογείς **δεν φαίνεται τίποτα** — ούτε αστεράκια. Είναι φυσιολογικό.
Κάνε επικόλληση με δεξί κλικ και πάτα Enter.

> ⚠️ **Τον κωδικό κρυπτογράφησης γράψ' τον και κάπου αλλού** — σε διαχειριστή
> κωδικών ή σε χαρτί στο συρτάρι. Αποθηκεύεται στον υπολογιστή με τρόπο που τον
> δένει σε αυτόν τον υπολογιστή και σε αυτόν τον λογαριασμό Windows. Αν ο
> υπολογιστής καεί, **τα αντίγραφα στο OneDrive δεν ανοίγουν χωρίς τον κωδικό**.

**Βήμα 2 — δοκιμαστικό αντίγραφο τώρα:**

```bash
.\backup-db.ps1
```

**Βήμα 3 — πες στα Windows να το κάνουν μόνα τους κάθε μέρα:**

```bash
.\install-task.ps1
```

Τελείωσες. Από εδώ και πέρα δουλεύει μόνο του.

## 5. Η καθημερινή ζωή

Κάθε βράδυ στις 03:00 ο υπολογιστής παίρνει αντίγραφο. Αν είναι κλειστός, το
παίρνει μόλις τον ανοίξεις.

**Μία φορά την εβδομάδα, ρίξε μια ματιά:**

```bash
Get-Content "$env:USERPROFILE\RentApp-Backups\backup.log" -Tail 5
```

Θες να βλέπεις γραμμές που τελειώνουν σε `Ολοκληρώθηκε`. Αν δεις `ERROR`, κάτι
πήγε στραβά εκείνο το βράδυ.

**Μία φορά τον μήνα, δοκίμασε ότι το αντίγραφο πραγματικά δουλεύει:**

```bash
.\verify-backup.ps1
```

Παίρνει το τελευταίο αντίγραφο, το επαναφέρει σε μια **προσωρινή τοπική** βάση,
μετράει τις γραμμές και μετά τη σβήνει. Η παραγωγή δεν αγγίζεται καθόλου. Θα σου
ζητήσει τον κωδικό του τοπικού PostgreSQL (του `postgres`).

Στο τέλος θες να διαβάσεις: *«Η άσκηση επαναφοράς πέτυχε»*.

> Γιατί έχει σημασία: ένα αντίγραφο που δεν το δοκίμασες ποτέ είναι υπόσχεση, όχι
> ασφάλεια. Οι περισσότερες καταστροφές δεδομένων γίνονται μόνιμες ακριβώς εκεί —
> υπήρχαν αντίγραφα, αλλά κανείς δεν είχε δοκιμάσει να τα ανοίξει.

## 6. Οι εντολές μία προς μία

### `backup-db.ps1` — παίρνει αντίγραφο

```bash
.\backup-db.ps1
```

Τι κάνει με τη σειρά: κατεβάζει τη βάση → την κρυπτογραφεί → **ανοίγει το ίδιο το
κρυπτογραφημένο αρχείο για να βεβαιωθεί ότι διαβάζεται** → το αντιγράφει στο
OneDrive → σβήνει τα πολύ παλιά → γράφει στο ημερολόγιο.

Κρατάει **7 ημερήσια, 4 εβδομαδιαία, 6 μηνιαία**. Δηλαδή μπορείς να γυρίσεις στο
χθες, στην προηγούμενη εβδομάδα ή σε έναν μήνα πριν, χωρίς να γεμίσει ο δίσκος.

### `verify-backup.ps1` — δοκιμή επαναφοράς

```bash
.\verify-backup.ps1
```

Με συγκεκριμένο αντίγραφο αντί για το τελευταίο:

```bash
.\verify-backup.ps1 -BackupFile "$env:USERPROFILE\RentApp-Backups\rentapp-20260903-0300.dump.enc"
```

### `restore-db.ps1` — επαναφορά ολόκληρης της βάσης

Για να δεις τι περιέχει ένα αντίγραφο, σε τοπική βάση που μένει για να την
κοιτάξεις με pgAdmin:

```bash
.\restore-db.ps1 -Target Local -Database RentDb_elegxos -Recreate
```

Σε βάση της Neon (π.χ. νέο branch):

```bash
.\restore-db.ps1 -Target Custom -ConnectionString 'postgresql://…'
```

Χωρίς `-BackupFile` παίρνει πάντα το νεότερο.

### `restore-tenant.ps1` — επαναφορά **μίας** εταιρείας

Βλ. σενάριο Β παρακάτω — είναι η πιο συχνή πραγματική ανάγκη.

### Πώς βλέπω τι αντίγραφα έχω

```bash
Get-ChildItem "$env:USERPROFILE\RentApp-Backups" -Filter '*.dump.enc' | Sort-Object Name -Descending | Select-Object Name, LastWriteTime
```

## 7. Τι κάνω όταν χαλάσει κάτι

### Σενάριο Α: έγινε λάθος πριν από λίγες ώρες

Αν **δεν έχουν περάσει 6 ώρες**, το γρηγορότερο είναι η ίδια η Neon:

1. Neon Console → το project → **Branches** → **Restore**.
2. Διάλεξε ώρα πριν το λάθος.
3. Η εφαρμογή συνεχίζει κανονικά, δεν αλλάζεις τίποτα.

Προσοχή: αυτό γυρίζει πίσω **όλες** τις εταιρείες.

### Σενάριο Β: θέλω να γυρίσω **μία εταιρεία** έναν μήνα πίσω

Αυτό είναι το δύσκολο σημείο μιας πολυ-μισθωτικής εφαρμογής, και αξίζει να το
καταλάβεις πριν το τρέξεις.

**Γιατί δεν κάνει μια απλή επαναφορά:** όλες οι εταιρείες μοιράζονται τους ίδιους
πίνακες και ξεχωρίζουν μόνο από τη στήλη `TenantId`. Αν επαναφέρεις ολόκληρη τη
βάση για να σώσεις τη μία, σβήνεις έναν μήνα δουλειάς **όλων των άλλων**.

**Τι κάνει το `restore-tenant.ps1`:**

1. Επαναφέρει το αντίγραφο σε **προσωρινή τοπική** βάση. Η παραγωγή δεν αγγίζεται.
2. Από εκεί ξεχωρίζει μόνο τις γραμμές της συγκεκριμένης εταιρείας — από 24
   πίνακες, με τη σωστή σειρά ώστε να μη σπάσουν οι συσχετίσεις.
3. Στην παραγωγή, **μέσα σε μία συναλλαγή**, σβήνει τις τωρινές γραμμές εκείνης
   της εταιρείας και βάζει τις παλιές. Αν οτιδήποτε πάει στραβά στη μέση, δεν
   αλλάζει τίποτα απολύτως.
4. Μετράει ξανά και επιβεβαιώνει ότι τα πλήθη ταιριάζουν.

**Βήμα 1 — δες τι θα γίνει, χωρίς να αλλάξει τίποτα:**

```bash
.\restore-tenant.ps1 -TenantName 'Επωνυμία' -TargetConnectionString 'postgresql://…' -BackupFile "$env:USERPROFILE\RentApp-Backups\rentapp-20260903-0300.dump.enc" -DryRun
```

Θα δεις πίνακα σαν αυτόν:

```
Πίνακας                   αντίγραφο       τώρα
────────────────────────────────────────────────
Customers                       100         28
Contacts                        193         50
Contracts                         4          0
```

Αριστερά τι είχε η εταιρεία τότε, δεξιά τι έχει τώρα. Εδώ φαίνεται καθαρά ότι
χάθηκαν 72 πελάτες και 4 συμβόλαια.

**Βήμα 2 — τρέξε το στ' αλήθεια** (ίδια εντολή, χωρίς `-DryRun`):

```bash
.\restore-tenant.ps1 -TenantName 'Επωνυμία' -TargetConnectionString 'postgresql://…' -BackupFile "$env:USERPROFILE\RentApp-Backups\rentapp-20260903-0300.dump.enc"
```

Θα σου ζητήσει να **γράψεις την επωνυμία** για επιβεβαίωση. Δεν είναι
γραφειοκρατία: είναι το τελευταίο φρένο πριν σβηστούν δεδομένα.

**Τι να ξέρεις πριν το κάνεις:**

- Γυρίζουν πίσω **όλα** τα δεδομένα εκείνης της εταιρείας: πελάτες, πάγια,
  συμβόλαια, δόσεις, πληρωμές. Ό,τι καταχωρήθηκε μετά το αντίγραφο **χάνεται**.
- Γυρίζουν πίσω και οι **χρήστες** της εταιρείας. Αν κάποιος άλλαξε κωδικό μετά
  το αντίγραφο, ισχύει ξανά ο παλιός. Αν προσλήφθηκε νέος υπάλληλος μετά, ο
  λογαριασμός του διαγράφεται και χρειάζεται νέα πρόσκληση.
- Οι άλλες εταιρείες **δεν θίγονται καθόλου**.
- Οι φωτογραφίες και τα δικαιολογητικά (αρχεία στο Cloudflare R2) **δεν**
  γυρίζουν πίσω — βλ. ενότητα 8.
- Τα ημερολόγια ενεργειών (`AuditLogs`) μένουν ως έχουν· είναι ιστορικό του τι
  συνέβη και δεν ξαναγράφεται.

**Αν θέλεις μόνο έναν πίνακα** — π.χ. διαγράφηκαν κατά λάθος πελάτες αλλά τα
συμβόλαια είναι σωστά — μην τρέξεις το παραπάνω. Επανάφερε το αντίγραφο σε τοπική
βάση με `restore-db.ps1 -Target Local -Database RentDb_elegxos -Recreate` και πες
μου· η αντιγραφή συγκεκριμένων γραμμών εξαρτάται από το ποιες συσχετίσεις τις
κρατούν.

### Σενάριο Γ: χάλασε όλη η βάση

Μη γράφεις πάνω στην υπάρχουσα. Δούλεψε σε νέο branch:

1. Neon Console → **Branches** → **New branch** (π.χ. `restore-20261003`).
2. Αντίγραψε το connection string του νέου branch.
3. `.\restore-db.ps1 -Target Custom -ConnectionString 'postgresql://…νέο branch…'`
4. Έλεγξε τη σύνοψη που τυπώνεται.
5. Azure Portal → App Service → **Environment variables** → άλλαξε το
   `ConnectionStrings__DefaultConnection` στο νέο branch → **Restart**.
6. Όταν σιγουρευτείς, σβήσε το παλιό branch.

### Σενάριο Δ: χάθηκε ο λογαριασμός Neon

1. Φτιάξε νέο project στη Neon (ή σε όποιον άλλο πάροχο PostgreSQL).
2. `.\restore-db.ps1 -Target Custom -ConnectionString '…'`
3. Άλλαξε το connection string στο App Service και κάνε restart.

Το αντίγραφο περιέχει και το σχήμα, όχι μόνο τα δεδομένα — δεν χρειάζεται τίποτε
άλλο.

## 8. Τι ΔΕΝ καλύπτεται

**Τα αρχεία στο Cloudflare R2.** Οι φωτογραφίες παγίων και τα δικαιολογητικά δεν
είναι μέσα στη βάση· η βάση κρατά μόνο τη διεύθυνσή τους. Αν σβηστεί το bucket,
η εφαρμογή θα δείχνει εγγραφές με σπασμένες εικόνες. Αν αυτό σε απασχολεί,
χρειάζεται ξεχωριστός συγχρονισμός των αρχείων.

**Μέρες με τον υπολογιστή κλειστό.** Η εργασία αναπληρώνει μόλις ανοίξεις τον
υπολογιστή, αλλά οι ενδιάμεσες μέρες δεν έχουν αντίγραφο. Αν θες αντίγραφα
ανεξάρτητα από το μηχάνημα, χρειάζεται προγραμματισμένη εργασία στο cloud.

## 9. Μηνύματα που θα δεις

| Μήνυμα | Τι σημαίνει |
|---|---|
| `Το connection string δείχνει στον pooler της Neon` | Φυσιολογικό. Η Neon δίνει διεύθυνση που δεν κάνει για αντίγραφα και το script τη διορθώνει μόνο του. |
| `Επαλήθευση εντάξει: 28 πίνακες με δεδομένα` | Το αντίγραφο ελέγχθηκε και διαβάζεται. |
| `LastTaskResult : 267009` | Η εργασία **τρέχει αυτή τη στιγμή**. Περίμενε και ξαναδές· θες τελικά `0`. |
| `Λάθος κωδικός ή αλλοιωμένο αρχείο` | Ο κωδικός δεν είναι σωστός ή το αρχείο χάλασε. Δοκίμασε άλλο αντίγραφο. |
| `Δεν βρέθηκε το μυστικό 'connection'` | Δεν έχει τρέξει το `init-secrets.ps1` σε αυτόν τον λογαριασμό Windows. |
| `Κενοί πίνακες: Installments` | Προειδοποίηση, όχι σφάλμα: ο πίνακας ήταν άδειος και στην πηγή. |

## 10. Κανόνες που δεν παραβιάζουμε

1. **Ο κωδικός κρυπτογράφησης υπάρχει και εκτός υπολογιστή.** Χωρίς αυτόν, τα
   αντίγραφα είναι ψηφιακά σκουπίδια.
2. **Ποτέ επαναφορά κατευθείαν πάνω στην παραγωγή.** Πάντα σε νέο branch ή σε
   τοπική βάση πρώτα, έλεγχος, και μετά αλλαγή του connection string.
3. **Τα αντίγραφα περιέχουν προσωπικά δεδομένα** — ΑΦΜ, τηλέφωνα, emails
   πελατών. Γι' αυτό κρυπτογραφούνται πριν φύγουν προς το OneDrive. Μην τα
   στέλνεις με email και μην τα αποκρυπτογραφείς σε κοινόχρηστο υπολογιστή.
4. **Μία φορά τον μήνα, `verify-backup.ps1`.** Είναι πέντε λεπτά.
